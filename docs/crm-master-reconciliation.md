# CRM master reconciliation

The importer adds normalized CRM company and location tables alongside the existing catalog. Local customer IDs, active states, orders, contacts, visits and position profiles are preserved. PartnerId identifies a CRM company; PartnerAddressId and Cod_Franciza identify a CRM location. PartnerCode and CIF remain distinct source fields. The original workbook is archived privately and verified by SHA-256. All non-manager row fields are retained in crm_locations.source_json, including blank values, the original representative and auxiliary identifiers. ManagerZona and ASMM never drive assignment.

Run tools/crm_master_reconcile.py plan with explicit --application, --workbook, --roster and --output paths. It reads the application without writing. Review additions, conflicts, addressReview and missingAddresses. The reviewed current roster must cover all active agents. Never supply historic CRM representatives as the current roster.

Run tools/crm_master_reconcile.py apply with --application, --plan and a new --receipt directory, first on a verified SQLite backup. Application writes are one transaction, fenced by complete customer, active-agent and profile snapshots. The tool verifies a recovery copy, foreign keys, catalog digest and unchanged protected tables. Repeating an applied source/plan is a no-op. The full before/after plan and receipt remain private.

CRM addresses are stored exactly in crm_locations. Operational addresses associated with saved profiles are retained because changing them invalidates map positions. Differences are explicitly reported for review. Missing addresses are filled from a matching franchise/company, exact company/address or a unique complete known company location. Multi-location companies are never assigned an arbitrary first store. Existing inactive records are not reactivated. An absent CRM row is never a deletion instruction.

After catalog validation, tools/crm_master_history.py exports new derived reference inputs and optionally reconciles the dedicated history database with --apply. It preserves original sale rows and source identities, excludes incompatible legacy franchise aliases from the new derived reference and reports these conflicts. Original catalog evidence remains intact. CRM rows without CIF use their PartnerCode only in the derived resolver input; raw missing CIF remains missing. Rebuild the activity snapshot with tools/build-partner-activity.mjs using the explicitly configured data directory. Verify source row/value/quantity totals, profile fingerprints and authorized agent/manager access before reporting completion.

No production paths, customer data, workbook snapshots, receipts or credentials belong in this repository. These tools do not geocode addresses or invent coordinates. Address completeness and map coverage are separate checks.
